# i18n 与外部语言文件架构

本文定义 Rivo UI 国际化、外部明文语言文件和模型默认回复语言的边界。语言文件是可编辑的展示数据，不是代码、权限配置或 prompt 扩展。

## 领域边界

```text
LocaleId (BCP 47)
  + LanguageCatalog (FTL UI messages)
  + response_language (内置 prompt 中的规范 locale 标签)

LanguageCatalog -> CLI/TUI 展示
response_language -> 下一次模型调用的内置 system prompt
policy/Intent/Event/protocol -> 不读取翻译结果
```

CLI/TUI 的 `language` 同时选择 UI locale 与默认 response language。UI 可立即切换；已构造的模型请求保持冻结，下一轮才读取新的 response language。用户任务明确指定语言时优先。

## 文件格式

每种语言是一个 `<locale>.ftl` 文件。文件为 UTF-8，最大 2 MiB，可以复制和人工编辑，不要求 hash、签名、压缩或编译。

```ftl
### rivo-language-schema: 1
### locale: zh-CN
### display-name: 简体中文
### revision: 2026-09-11.1
### min-rivo-version: 0.1.0

common-ok = 确定
common-cancel = 取消
error-language-invalid = 不支持的语言：{ $locale }
```

metadata 使用文件开头连续的 `### key: value` Fluent comment。必填字段为 schema、locale、display-name 和 revision；最低版本可省略。locale 必须规范化后与文件名一致；`min-rivo-version` 必须是受支持的 SemVer，且不得高于当前 Rivo 版本。revision 是供人阅读和更新比较的标识，不证明文件完整性或来源。

message ID 是稳定 API。bundled `en-US.ftl` 是规范 key/变量集合，bundled `zh-CN.ftl` 必须完整匹配。外部 locale 可以缺 key，但已提供 key 的变量集合必须与英文规范一致；未知 key 忽略并诊断。解析失败、重复 ID、metadata 错误或变量不一致会拒绝整份候选文件。为避免终端控制序列伪造可见 UI，文件拒绝除换行、回车和 Tab 外的 Unicode control character；`display-name`、`revision` 与 `min-rivo-version` 另有短文本长度限制且不得含 control character。

## 发现与回退

按以下顺序发现同名 locale：

1. `RIVO_LANGUAGE_DIR` 显式指定的用户目录；未设置时使用 `<data_root>/rivo/languages`。
2. 随程序提供并编译进二进制的 `en-US`/`zh-CN` bundled 资源。
3. 二进制内置的完整 `en-US` 紧急资源。

高优先级文件可部分覆盖低优先级同 locale；消息级回退最终到 embedded English。catalog 在内存中不可变，reload 先完整构建候选 catalog，成功后才替换引用；失败继续使用旧 catalog。没有后台文件 watcher。

## 本地管理

用户可以直接复制 `<locale>.ftl` 到 `rivo language path` 返回的目录。`RIVO_LANGUAGE_DIR` 显式覆盖该用户目录，否则使用 `<data_root>/rivo/languages`。`validate <file>` 只读检查规范文件名、metadata、格式和英文变量 schema；文件读取最多消耗 2 MiB + 1 byte，并拒绝文件级 symlink/reparse。`install <file>` 从 metadata 取得规范 locale 后原子写入。首次安装采用 no-clobber 原子落盘且不需确认，覆盖已有文件必须传 `--yes` 并保留一个 `<locale>.ftl.bak`。`remove <locale> --yes` 只删除用户层文件，不删除 bundled fallback。`list` 保留损坏文件并显示错误，不因单个损坏文件隐藏其他语言。运行中的 TUI 通过 `/language reload` 明确重载。

直接 copy 的文件在下一进程启动时发现；运行中的 TUI 使用 `/language reload` 显式重载，会重新生成 discovery snapshot 和当前目标 catalog，全部成功后才替换当前引用。`/language <locale>` 切换到已安装 locale，`/language` 显示当前和可用 locale。人工编辑不触发修改检测，也不需要更新 hash。当前默认 locale 文件缺失或无效时 UI 回退 embedded English，并给出本地修复命令；合法 locale ID 仍可作为模型 response language。

## 显式远程管理

Rivo 提供 `rivo language remote-list|download|update|rollback`，但不会在启动、resume、TUI reload 或后台任务中访问网络。每次远程访问都必须由用户命令显式触发，并接受本次命令指定的 HTTPS registry URL；不接受绕过 registry 摘要约束的裸文件 URL 下载。URL 必须没有 userinfo，重定向的每一跳仍须为 HTTPS；响应具有固定超时和大小上限。

registry 使用有界 JSON schema 1，每项只包含规范 locale、display name、revision、HTTPS download URL、文件字节数和 SHA-256。下载先写入用户语言目录之外的受限临时文件，同时计算长度与 SHA-256；摘要匹配后仍须执行与本地 `validate` 相同的 UTF-8、metadata、locale、版本、key 和变量 schema 校验，全部成功才复用原子安装路径。覆盖必须显式确认并保留一个 `.bak`。

成功下载保存不含凭据的本地 receipt，字段限于 locale、去除 query/fragment 的来源 URL、revision、字节数、SHA-256 和安装时间。`update` 只在显式调用时读取 receipt 并重新执行完整下载校验；revision 只用于比较，不能替代摘要或 FTL 校验。`rollback` 不联网，只完整验证同 locale 的 `.bak` 后原子恢复。任何失败都不得改变现有语言文件、receipt、discovery snapshot 或活动 catalog。

远程语言包仍是不可信 UI 数据。registry、receipt 和 `.ftl` 的任何文本都不得进入 system/mode prompt、命令路由、policy、Intent/Event 或机器协议；prompt 只接收规范化后的 locale ID。

## Prompt 与协议

system/core/mode prompt 保持编译期或随版本受控的内置资产。外部 `.ftl` 的字节不得进入 `PromptEnvelope`；prompt 只接收经过验证的规范 locale ID，并加入默认回复语言要求。revision 包含内置 prompt revision、mode 和 response locale。

app-server 只暴露 `response_language`，宿主自行管理 UI。JSONL、JSON-RPC、A2A、instance-control、日志和审计的字段、枚举、error code、canonical message、签名与哈希输入不本地化。安全确认的按键到领域值映射也不读取语言文件。

## 首批实现边界

当前实现包括 LocaleId、FTL metadata/文件解析、规范 key/变量校验、discovery/catalog、fallback、bundled 文件和本地/远程语言管理。schema 6 的 `defaults.locale`、CLI `--language`、Session/Turn journal、prompt 默认回复语言和 app-server `response_language` 已接入。发布归档包含 `en-US` 与 `zh-CN`，归档 smoke 校验语言资源。CLI/TUI 仍有未完全本地化的文字；机器协议和错误码保持固定，不承诺所有文案已翻译。真实终端显示需在实际终端另行核验。
