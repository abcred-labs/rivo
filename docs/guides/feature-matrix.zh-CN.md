# Rivo 功能矩阵：本地与远程接入

本文维护公开运行时的能力与客户端/宿主入口差异。接口或平台限制变化时须同步更新本页。

> 本页描述源码能力与接口限制。整体架构见[新用户导读](architecture-and-capabilities.zh-CN.md)，发布验收及未验证边界见[发布流程](../runbooks/releasing.zh-CN.md)。

“已实现/接口”表示代码或协议存在；能否在指定平台交付，还须以对应提交的 CI 与构件运行证据确认。

## 1. 能力类别与两种“模式”

- **产品能力类别**：CLI/TUI 是直接面向用户的本地终端执行能力；Desktop App 与 Remote Agent Node 是复用运行时的延展/基座能力。分别的机制、接入步骤和基座矩阵见[基座接入说明](runtime-integration.zh-CN.md)。
- **接入形态**：本地 CLI、TUI、Desktop，或远程 Web、Mobile；决定用户从哪里操作、如何连接运行时。
- **任务模式**：`general`、`research`、`plan`、`coding`、`review`；决定 Agent 如何组织任务与基础工具集。

因此，“远程 coding”表示通过远程客户端操作执行端的编码 Agent，**不是在手机或浏览器里直接运行完整工具链**。CLI/TUI 通过 SSH 使用时仍属于远端机器上的 CLI/TUI，不等于已经交付 Web/Mobile 客户端。

### 接入形态与责任边界

| 接入形态 | 用户界面在哪里 | Agent 与工具在哪里执行 | 当前责任边界 |
| --- | --- | --- | --- |
| 本地 CLI | 执行端的命令行 | 同机 Rivo runtime | 本仓库已有实现；发布目标为 Windows amd64、Linux amd64/arm64、macOS amd64/arm64，系统专属工具另有限制。 |
| 本地 TUI | 执行端的终端交互界面 | 同机 Rivo runtime | 本仓库已有实现，与 CLI 共用内核。 |
| 本地 Desktop | 图形桌面客户端 | 通过本机宿主连接 Rivo runtime | Desktop 由独立仓库负责；本页只核验中立 app-server 接口，不声明 Desktop UI 已支持矩阵中的功能。 |
| 远程 Web | 用户浏览器 | 宿主所在执行端的 Rivo runtime | 当前仅有可供宿主复用的本机接口；本仓库没有因此交付完整远程 Web 客户端/接入服务。 |
| 远程 Mobile | 手机或平板客户端 | 宿主所在执行端的 Rivo runtime | 与 Web 类似，另需移动端 UI、连接恢复和交互适配，不能推断已有原生 App。 |

本机宿主既可以服务本地图形界面，也可以作为未来远程接入链路中的适配层：

```text
本地 CLI / TUI ───────────────────────────────→ Session / Agent
本地 Desktop → 本机宿主 → app-server ─────────→ Session / Agent
远程 Web / Mobile → 认证与授权服务 → 本机宿主 → app-server → Session / Agent
                     └──────── 候选适配层；不是已交付的远程服务 ────────┘
```

app-server 当前提供本机 stdio 与 Windows Named Pipe，不是可让浏览器或手机直接连接的公网 HTTP/WebSocket API。A2A 是独立的 Agent 互操作边界，不替代面向终端用户的登录、账户与客户端协议。

本页的 Web/Mobile 列只表示 **Remote Agent Node 的宿主 + app-server 路径**，不是全部远程节点能力。A2A Server 是另一条已有代码的受控任务接入路径，其任务模式、Web/Browser、记忆和审批边界不同；具体比较见[两种基座的能力支持矩阵](runtime-integration.zh-CN.md#4-两种基座的能力支持矩阵)。

## 3. 当前功能矩阵

以下 Desktop、Web、Mobile 列均按**中立 app-server 接入路径**核验，不包含客户端私有扩展，也不假设宿主可以启动任意 Shell 来绕过接口限制。

### 3.1 任务与工具能力

| 功能 | 本地 CLI | 本地 TUI | 本地 Desktop 接口 | 远程 Web 适配 | 远程 Mobile 适配 |
| --- | --- | --- | --- | --- | --- |
| 提交任务、流式文本与最终结果 | 已实现 | 已实现 | 接口 | 接口＊ | 接口＊ |
| 选择 `plan` / `coding` | 已实现 | 已实现 | 接口：`plan` / `code` | 接口＊ | 接口＊ |
| 显式选择 `general` / `research` / `review` | 已实现 | 已实现 | 不支持 | 不支持 | 不支持 |
| 执行端文件读取、目录浏览与搜索 | 已实现 | 已实现 | 接口：由 Agent 调用 | 接口＊ | 接口＊ |
| 执行端文件修改、patch、移动与受控删除 | 已实现：`coding` | 已实现：`coding` | 接口：`code` + policy | 接口＊ | 接口＊ |
| 结构化进程执行、调用已有构建/测试工具 | 已实现：`coding` | 已实现：`coding` | 接口：`code` + policy | 接口＊ | 接口＊ |
| 显式原始 Shell 通道 `shell_exec` | 已实现：`--shell`，需确认 | 不支持 | 不支持 | 不支持 | 不支持 |
| Web fetch / Brave Search | 已实现：`--network` | 已实现：本轮开关 | 不支持 | 不支持 | 不支持 |
| Browser：执行端 loopback CDP 页面交互 | 已实现：`--browser` | 已实现：本轮开关 | 不支持 | 不支持 | 不支持 |
| 选择已配置 MCP server / toolset | 已实现 | 已实现 | 接口：仅本机 allowlist 引用 | 接口＊ | 接口＊ |
| 召回已确认的执行端工作区记忆 | 已实现：可关闭 | 已实现：可关闭 | 接口：默认启用，无切换字段 | 接口＊：同左 | 接口＊：同左 |
| 内部子代理委派与并发控制 | 已实现 | 已实现 | 已实现：按配置默认开启，可经 `runtime_settings` 关闭或限流，待新候选复测 | 不支持 | 不支持 |
| 本轮显式选择 A2A peer 并委派 | 已实现 | 已实现 | 不支持：无 peer 选择字段 | 不支持 | 不支持 |

这里的“文件操作接口”指 `turn/start` 驱动 Agent 使用工具，**不是通用文件上传下载、远程文件浏览器或任意进程执行 RPC**。工具所在路径、命令和权限均属于执行端。

特别注意：

- app-server 的 `collaboration_mode` 目前只接受 `plan/code`。通过 prompt 请求“做研究”可以得到相关回答，但不等于切换到了 `research` 模式及其完整契约。
- `turn_options` 明确关闭 `network`、`browser`、`shell`，A2A peers 为空；不能因为底层 Session 支持这些字段就将宿主入口标为支持。`subagents_enabled`/`max_subagents` 已作为显式 `runtime_settings` 开放，默认跟随本机配置。
- “MCP 可接入”不意味着允许远端安装 server、提交命令、URL 或凭据。显式事实核验触发的只读 toolset 补全规则仍受执行端配置与 policy 限制。
- 远程 Web 客户端使用浏览器显示 UI，与 Agent 的 Browser/CDP 工具是两件事。

读表时还应保留以下边界：

1. **历史查询不等于完整同步**：bridge 的持久记录查询主要提供 ID、时间、状态等元数据；运行事件有大小限制与脱敏。不能据此承诺跨端完整 transcript、原始工具参数/结果或文件附件同步。
2. **确认不等于远端拥有本机权限**：bridge 的 allow 映射为一次性授权，不能代替宿主对用户身份、工作区归属和审批权的校验；客户端自报身份不是授权。
3. **模型选择不等于连接管理**：运行设置只引用本机有效目录；`model_routing/*` 配置 RPC 是另一组有 revision、影响计划和确认约束的接口，不因能提交任务就自动允许远程调用。
4. **凭据不跨端回传**：`credential/upsert` 的本机 stdio 边界不能扩展到 Named Pipe、A2A/LAN 或 Web/Mobile 中继；客户端界面不应索取执行端已有密钥正文。
5. **执行端恢复不等于移动端可靠重连**：`session/resume` 和有界事件订阅可以复用，但不保证断网后无限续跑、跨进程完整事件重放或“恰好一次”执行。stdio EOF 会取消活动任务；新宿主进程需要显式恢复会话。

当前实现依据：[CLI 参数与 TUI 宿主](../../runtime/crates/cli/src/main.rs)、[TUI 启动设置](../../runtime/crates/tui/src/startup.rs)、[app-server 的 RuntimeSettings、turn_options 与请求分发](../../runtime/crates/cli/src/app_server.rs)。协议依据：[app-server 协议](../architecture/app-server-protocol.zh-CN.md)与[本机宿主运行手册](../runbooks/app-server-local-host.zh-CN.md)。

## 4. 目标矩阵：哪些可以复用，哪些仍需规划

本节是为了讨论“希望各端能做什么”的**候选适配目标**，不是把上节的不支持改写成已经支持。Desktop 不在本仓库定义目标；Web/Mobile 如需实施，必须在责任仓库正式立项并明确契约、测试和证据。本次仅增加说明文档，不新增 Feature 或解冻现有范围。

| 目标能力 | 本地 CLI / TUI | 本地 Desktop | 远程 Web 候选目标 | 远程 Mobile 候选目标 |
| --- | --- | --- | --- | --- |
| 核心闭环：提交、流式查看、确认、取消、恢复 | 保持现有能力 | 依独立仓库规划；本地接口可复用 | 规划†：优先适配现有接口 | 规划†：优先适配现有接口与小屏交互 |
| 五种任务模式一致选择 | 保持五模式 | 依独立仓库规划及中立契约演进 | 规划†：需先扩展模式协商，当前仅两种 | 规划†：同 Web |
| 执行端文件、构建/测试、MCP | 保持受控执行 | 当前核心接口可复用，UI 以独立仓库为准 | 规划†：先支持远端任务执行，不默认开放文件传输 | 规划†：以提交、查看和确认为主，执行仍在服务端 |
| Web、Browser、A2A 能力对齐 | 已有入口，受各自配置限制 | 不在此页承诺扩展 | 规划†：需逐项 capability 协商与授权设计；当前不支持 | 规划†：同 Web，不承诺与桌面交互完全等价 |
| 登录、工作区授权、断线恢复与审计 | 不新增远程职责 | 由其产品范围决定 | 规划†：属于远程宿主的必要前置能力 | 规划†：另考虑后台挂起、弱网、重复提交 |
| 任意读写手机/浏览器设备文件、远程取回执行端密钥、跳过 policy | 不因接入形态扩大权限 | 不由中立接口授予 | 不支持：不得作为默认适配目标 | 不支持：不得作为默认适配目标 |

当前没有将上述远程候选目标分配给 V1/V2/V3 的发布承诺。FEAT-024 中心监督仅保留未来设计参考，本仓库不再交付中心监督服务，也不承诺 V2 实现；它不等于完整 Web/Mobile 产品。本阶段也不支持以本页为依据实现 WebSocket v2。公开交付范围以本矩阵和版本发布说明为准。

## 5. 远程适配必须回答的五个问题

1. **谁能连上谁？** 宿主负责认证、传输加密、身份与执行端绑定；不能直接向外暴露本机 stdio/Named Pipe。
2. **谁能看哪个工作区？** 每次读历史、订阅事件、提交任务或审批，都需要在宿主侧检查归属；当前 bridge 的本机工作区校验不是多租户隔离。
3. **谁有审批权？** 将 interaction 与用户、Session、Turn 和请求身份绑定。默认拒绝无法识别、已过期或无合法审批人的操作。
4. **断线后发生什么？** 明确运行生命周期、取消与自然完成的竞争、恢复游标、幂等重试和重复审批处理；不能把网络重试变成重新执行副作用。
5. **哪些数据会到客户端？** 默认使用有界脱敏事件。若需要附件、完整历史、截图或推送，必须另定权限、留存和数据传输契约，不能直接透传工具或 Provider 原始内容。

这些是候选设计与验收前提，不表示本仓库已实现远程认证、云端托管、推送服务或多用户平台。

## 6. 如何选择

- **希望立即体验尽可能完整的当前能力**：优先本地 TUI；需要命令自动化时用 CLI。
- **希望嵌入本地图形产品**：评估 app-server 已开放的接口，再核对 Desktop 独立仓库的实际实现，不能假定与 CLI/TUI 等价。
- **希望通过 Web/Mobile 控制执行端**：先交付远程宿主的身份、授权和连接生命周期，再适配“提交 → 观察 → 确认 → 取消/恢复”的最小闭环。
- **希望多个独立 Agent 协作**：评估 A2A，而不是把它当作 Web/Mobile 客户端协议。
